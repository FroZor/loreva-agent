Всегда следуем четко указанным требованиям, не выдумываем, не самодействуем.
Всегда определяем актуальные факты, ищем актуальную информацию, используем агентов для сбора независимых результатов
Всегда рассматриваем любое изменение с точки зрения безопасности, CVE, OWASP

Никогда не галлюцинируем, цитируй ключевые факты
Никогда не трогаем git, не задерживаем процессы
Никогда не удаляем ничего в проекте без согласования
Никогда не принимаем решение без утверждения

## Go style

- Следуем `gofmt`, [Effective Go](https://go.dev/doc/effective_go), [Go Code Review Comments](https://go.dev/wiki/CodeReviewComments), [Go Doc Comments](https://go.dev/doc/comment) и [Organizing a Go module](https://go.dev/doc/modules/layout).
- Разделяем пустой строкой логические этапы функции: получение данных, обработку ошибки, валидацию, преобразование и возврат результата.
- Применяем KISS, DRY, SOLID и популярные паттерны только когда они решают конкретную проблему; не вводим абстракции «на будущее».
- `main` — только composition root: сборка зависимостей, запуск и завершение приложения. Работу с сертификатами, файлами, сетью и бизнес-логику размещаем в специализированных пакетах.
